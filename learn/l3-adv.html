CiA 402 驅動狀態機

🎯 會用 Controlword/Statusword 把伺服從上電帶到使能，會處理 Fault。

CiA 402 是 IEC 61800-7 標準化的驅動 profile — 不管底下是 CANopen 還是 EtherCAT CoE，狀態機都一樣（所以專案 A、B 共用這一節）。核心是三個 OD 物件：

物件方向作用
0x6040 Controlword主站 → 驅動命令：Shutdown(0x06) → Switch On(0x07) → Enable Op(0x0F)；Fault Reset(0x80)
0x6041 Statusword驅動 → 主站目前狀態（bit 遮罩解碼，見下）
0x6060 Modes of operation主站 → 驅動運行模式（L3-14）
使能交握 — 本 repo 把「查表推下一步」封裝成一個純函式（cia402.h）
/* 每個控制週期呼叫：依 statusword 回推下一步 controlword，
 * SWITCH_ON_DISABLED → READY → SWITCHED_ON → OPERATION_ENABLED
 * 若在 FAULT 則回 CW_FAULT_RESET。純函式、無狀態、可單元測試。 */
uint16_t cia402_enable_step(uint16_t statusword);

cia402_state_t st = cia402_decode(sw);      /* DS_OPERATION_ENABLED? DS_FAULT? */
uint16_t cw = cia402_enable_step(sw);
co_pdo_send_csp(bus, node, cw, target);     /* 交握與控制走同一個 RPDO */
設計亮點：把狀態機寫成「statusword 進、controlword 出」的純函式，而不是自己記狀態 — 驅動器才是真相來源，主站重開機、驅動器掉電重上都不會錯亂。firmware/tests/test_cia402.c 直接對這個函式打單元測試。
💻 對照範例：learn/examples/l3/01-cia402-sm/（含自我斷言的可跑版）；repo 實例 firmware/canopen/cia402.h/.c。
0x6040/0x6041enable 交握Fault Reset純函式狀態機

運行模式（CSP/CSV/CST）與單位換算

🎯 懂為什麼機器人選 CSP，會做 rad ↔ counts 換算。
模式（0x6060）值誰算軌跡用途
PP 輪廓位置1驅動器點到點、單軸調機
HM 回零6驅動器開機找原點（增量編碼器才需要）
CSP 循環同步位置8主站每週期給位置多軸協同 — 本專案主模式
CSV / CST 同步速度/轉矩9 / 10主站速度控制 / 力控、阻抗控制
CSF 同步力控13主站EYOU 力控關節專屬（PHU 手冊 §4.3）

為什麼多軸要 CSP：14 個關節要走出一條直線軌跡，插補必須由「看得到全部關節」的主站統一算，驅動器只負責緊跟每 2ms 一個的位置點。

單位換算 — EYOU PHU 輸出端 19-bit 絕對編碼器（robot_config.c）
/* 19-bit = 524288 counts / 輸出圈 → counts per rad */
#define CPR_19BIT (524288.0f / (2.0f * PI_F))

int32_t target_counts = (int32_t)(q_rad * CPR_19BIT);      /* rad → counts 下發 */
float   q_fb = js_counts_to_rad(j, pos_actual);            /* counts → rad 回授 */
實戰教訓：單位換算是伺服整合最容易炸的地方 — 到底是「馬達端 counts × 減速比」還是「輸出端 counts」？EYOU 另有走「馬達端 19-bit × 減速比 101 = 52953088 counts/輸出圈」的介面組態（本 repo EtherCAT 路線實測）。上電第一件事：手轉一圈，讀回授驗證換算，再談使能。
💻 對照範例：learn/examples/l3/02-units/（兩種組態對照 + 往返驗證）；repo 實例 firmware/app/robot_config.c、firmware/control/joint_space.c 的 js_counts_to_rad()；PHU 規格見 doc_EYOU/、docs/design/eyou-phu-motor-analysis.md。
CSP=8插補週期counts/rad減速比 101

運動學 · IK · 軌跡（joint-space / task-space）

🎯 從「控制一顆馬達」升級到「控制一隻手臂」：FK/IK、平滑軌跡、分層控制。

本 repo 的控制棧是乾淨的四層，每層各自可測（firmware/control/）：

層模組做什麼
L4 雙臂協同dual_arm_ctrl.c左右臂模式（獨立/鏡像/協同）＋ 末端最小距離 5cm 防撞
L3 task-spacetask_space.c、ik.c、kinematics.cDH 正運動學 + 數值 IK：末端位姿 → 7 軸關節角
L2 joint-spacejoint_space.c、trajectory.c限速限加速度的平滑軌跡 + rad↔counts
L1 通訊firmware/canopen/把 counts 用 CSP PDO 送出去（L2-10）
每個 2ms tick 的資料流（app_main.c 實碼節錄）
float q_fb[14];                              /* 1) 回授 counts→rad 回灌 */
for (int j = 0; j < 14; j++)
    q_fb[j] = js_counts_to_rad(j, g_jstate[j].pos_actual);
da_ctrl_sync_feedback(&s_dc, q_fb);

int32_t cnt[14];                             /* 2) L4協同→L3 IK→L2軌跡→counts */
da_ctrl_tick_1khz(&s_dc, cnt);

for (int j = 0; j < 14; j++)                 /* 3) L1 CSP 下發 */
    dual_arm_set_target(j, cnt[j]);
dual_arm_tick();
  • 7-DoF 冗餘：手臂比 6 自由度多 1，IK 有無限解 → 數值法（Jacobian）+ 姿態偏好
  • 軌跡限制：目標一步跳太遠會觸發驅動器 following error → trajectory 層限速/限加速度
  • 矩陣運算自寫輕量 linalg.c（嵌入式沒有 Eigen 可用）
💻 對照範例：learn/examples/l3/03-ik-2link/（2 連桿把 FK→IK→直線走一遍）；repo 實例 firmware/tests/test_ik.c、test_kinematics.c、test_trajectory.c；設計文件 docs/design/wp3-joint-space.md、wp4-task-space.md、wp5-dual-arm-integration.md。

安全機制 — 看門狗 · 急停 · 使能門檻

🎯 學會把「會動的東西」做到敢上電：失聯偵測、安全停止、狀態門檻。
威脅對策repo 實作
某軸失聯（斷線/當機）每軸通訊看門狗 50mssafety_report_joint() + safety_update()
驅動器報 Fault解析 statusword、全系統反應safety.c 收 0x6041
人要它停急停 API + 硬體 STOapp_set_estop()；PHU 有 STO 接點
未就緒就動RUNNING 門檻：沒到門檻目標鎖在實際位置app_main_tick() 的 run 判斷
app_main.c — 一個真實 bug 的教訓（修正後的註解原文）
/* WP6 安全：只在「真的收到新 TPDO」的軸更新看門狗時間戳,
 * 否則某軸失聯時 last_ms 會被持續刷新而永遠偵測不到（修正前的 bug）。 */
for (int j = 0; j < 14; j++)
    if (g_jstate[j].fb_fresh)
        safety_report_joint(j, g_jstate[j].statusword, now);
bool allow = safety_update(now);
dual_arm_set_safe_stop(!allow, safety_safe_controlword());
看門狗的第一定律：「餵狗」的條件必須是真的有新資料，不是「這段程式碼有跑到」。上面那個 bug（無條件刷新時間戳 → 失聯永遠測不到）是安全系統最典型的自我安慰式失效。
💻 對照範例：learn/examples/l3/04-watchdog-fbfresh/（buggy vs fixed 一跑就懂）；repo 實例 firmware/safety/safety.h/.c、firmware/tests/test_safety.c、docs/design/wp6-safety-wp7-host.md；安全停止的 controlword 策略見 safety_safe_controlword()。

EtherCAT 入門 — 突破 CAN 的頻寬天花板

🎯 懂 EtherCAT 的四大概念（ESM/DC/CoE/ESI），知道它怎麼解掉 L2-11 的 1kHz 問題。

EtherCAT 用 100Mbps 乙太網實體層，frame「飛過去的路上」被每個從站即時讀寫（on-the-fly）— 14 軸 @1kHz 的資料量只占頻寬的零頭。四個必懂概念：

概念一句話對照 CANopen
ESM 狀態機INIT → PREOP → SAFEOP → OP，每階段能做的事不同NMT 狀態機（L2-8）
CoECANopen over EtherCAT — SDO/PDO/CiA402 原封不動搬過來L2-9/10、L3-13 全部直接沿用
DC 分散時鐘硬體級同步，全網從站對時 <1µs（SYNC0 中斷）CANopen SYNC 訊息（軟體級、ms 級）
ESI 檔從站的 XML 身分證：PDO 佈局、同步模式EDS 檔
SOEM（開源主站庫）最小流程 — 掃描到 OP
ec_init("enp2s0");                          /* 綁一張實體網卡(raw socket) */
ec_config_init(FALSE);                      /* 掃描從站,讀 EEPROM/ESI */
printf("found %d slaves\n", ec_slavecount);

ec_config_map(&IOmap);                      /* PDO 映射進行程記憶體 */
ec_configdc();                              /* 啟用分散時鐘 */
ec_statecheck(0, EC_STATE_SAFE_OP, EC_TIMEOUTSTATE);
ec_slave[0].state = EC_STATE_OPERATIONAL;   /* SAFEOP → OP:開始交換過程資料 */
ec_writestate(0);
/* 之後每 1ms: ec_send_processdata() + ec_receive_processdata() */
學習投資報酬率：因為 CoE 的存在，你在 L2/L3 學的 SDO、PDO、CiA402 在 EtherCAT 上原樣有效 — 換的只有「載體」（bxCAN → 乙太網）和「同步」（無 → DC）。這就是先學 CANopen 再學 EtherCAT 的理由。
💻 對照範例：learn/examples/l3/05-ecat-skeleton/（無 SOEM 也能編的 dry-run + 真機建置法）；本 repo EtherCAT 系列分支（feature/linux-rt-ethercat-master 等）將 SOEM/IgH 原始碼收在 third_party/；選型比較見 docs/design/canopen-vs-ethercat.md。

Linux 即時主站 — PREEMPT_RT 與 1kHz 迴圈

🎯 讓一般 PC 跑出「準時的 1ms」：RT kernel、排程、CPU 隔離、抖動量測。

EtherCAT 主站通常跑在 Linux PC 上，但普通 kernel 的排程延遲可到毫秒級 — 1kHz 迴圈直接爆。四件套：

  • PREEMPT_RT kernel：apt install linux-image-rt-amd64 級別的低延遲搶佔
  • SCHED_FIFO 高優先權 + mlockall 鎖記憶體防 page fault
  • CPU 隔離：isolcpus=2,3 把控制迴圈釘在獨占核心上
  • 先量再信：cyclictest 量 max latency，沒過關不用談控制
1kHz 即時迴圈骨架（clock_nanosleep 絕對時間法）
struct sched_param sp = { .sched_priority = 90 };
pthread_setschedparam(pthread_self(), SCHED_FIFO, &sp);
mlockall(MCL_CURRENT | MCL_FUTURE);          /* 不准 swap/page fault */

struct timespec next;
clock_gettime(CLOCK_MONOTONIC, &next);
while (running) {
    next.tv_nsec += 1000000;                 /* +1ms,絕對時間不累積漂移 */
    if (next.tv_nsec >= 1000000000L) { next.tv_sec++; next.tv_nsec -= 1000000000L; }
    clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &next, NULL);

    ec_send_processdata();                   /* 與 DC SYNC0 對齊的過程資料交換 */
    ec_receive_processdata(EC_TIMEOUTRET);
    control_tick();                          /* 同一套 L2~L4 控制棧 */
}
💻 對照範例：learn/examples/l3/06-rt-1khz/（1kHz 迴圈 + 抖動統計，普通權限就能跑）。
