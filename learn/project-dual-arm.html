🦾 專案 A — 雙臂 CANopen 主站（本 repo 主線）

STM32F746ZG 當主站，雙路 bxCAN 各帶一臂 7 顆 EYOU PHU 關節，CANopen CiA 301/402 · CSP 模式 · 500 Hz 全棧控制。這就是 firmware/ 目錄的完整內容。
STM32F746ZGbxCAN ×2 @1MbpsCiA 301/402 CSP @500Hz14 軸 PHU

🗺️系統架構

一顆 MCU、兩條獨立匯流排、十四顆整合式諧波關節。左右臂各自一條 bus：頻寬夠用、故障隔離。

為什麼 500 Hz 而不是 1 kHz：L2-11 算過 — 單臂 7 軸每週期 14 frame，500 Hz = 7000 frame/s 已到 Classic CAN 上限的 ~90%。要 1 kHz 就是專案 B（EtherCAT）的事。

🔩硬體清單 · 接線要點

項目規格備註
主控板STM32F746ZG（Nucleo-144 可）雙 bxCAN 是選型關鍵（L1-1）
CAN 收發器 ×2TJA1051 / SN65HVD230 等 3.3V 款MCU 只有控制器，沒有收發器
關節 ×14EYOU PHU20 ×4、PHU17 ×4、PHU14 ×624–48V 供電、菊鏈 CAN In/Out、STO 接點
電源48V 主電 + 邏輯電分開大關節煞停回灌，電源要能吸收
  • 腳位（依板調整）：CAN1 PD0=RX / PD1=TX；CAN2 PB12=RX / PB13=TX（firmware/README.md）
  • 每條 bus 兩端 120Ω；量 CAN_H–CAN_L 靜態約 60Ω 驗證
  • 節點 ID / 波特率用 SDO 組態（0x26A1 預設 1Mbps，見 PHU 手冊）
  • STO 迴路先接常閉急停鈕再上 48V — L3-16 不是選配

🏁里程碑 — 本 repo 實際走過的 WP2 → WP7

每個里程碑都有對應的設計文件與測試，照順序打勾。這份順序（單軸 → 關節空間 → 任務空間 → 雙臂 → 安全 → 上位機）就是伺服整合的標準教科書流程。

M1

WP2 · 單軸 bring-up

🎯 一顆關節：SDO 讀得到 → NMT 進 OP → CiA402 使能 → CSP 微動。
  • candump/邏輯分析儀看得到 heartbeat（L2-8）
  • SDO 讀 0x1000/0x6041 成功（L2-9）
  • cia402_enable_step() 交握到 OPERATION_ENABLED（L3-13）
  • 手轉一圈驗證 counts↔rad 換算（L3-14 的教訓）
  • CSP 下發 ±1000 counts 小步階，軸有跟
📄 文件：docs/design/wp2-single-axis-bringup.md
M2

WP3 · joint-space 控制

🎯 7 軸同 bus：500Hz tick 下平滑軌跡點到點，無 following error。
  • TIM6 2ms tick 掛上 app_main_tick()（L1-6）
  • trajectory 層限速限加速度生效（L3-15）
  • bus 載荷實測，dual_arm_tx_drops() = 0
📄 文件：docs/design/wp3-joint-space.md；測試 test_trajectory.c
M3

WP4 · task-space（IK）

🎯 給末端位姿，手臂走直線；IK 在 2ms 預算內收斂。
  • FK 與機構圖對照無誤（test_kinematics.c）
  • IK 誤差/迭代數在預算內（test_ik.c）
  • 末端畫直線/圓弧，實測軌跡貼合
📄 文件：docs/design/wp4-task-space.md
M4

WP5 · 雙臂整合

🎯 14 軸雙 bus 同時跑；獨立/鏡像/協同三模式；防撞生效。
  • CAN1/CAN2 同 tick 內都完成 PDO 交換
  • da_ctrl 三模式切換正常
  • 兩臂末端逼近到 5cm，防撞 hold 觸發（app_safety_hold()）
📄 文件：docs/design/wp5-dual-arm-integration.md
M5

WP6 · 安全

🎯 拔線、報 Fault、按急停 — 每一種都要在 50ms 級別內安全停下。
  • 拔任一軸 CAN 線 → 看門狗觸發安全停止（L3-16 的 fb_fresh 教訓）
  • estop API + STO 實測
  • test_safety.c 全綠
📄 文件：docs/design/wp6-safety-wp7-host.md
M6

WP7 · 上位機介面

🎯 UART 文字協定：設定模式/目標位姿、讀狀態 — 系統可被外部指揮。
  • host_if.c 命令解析 → app_set_left_pose() 等 API
  • 狀態回報含 app_sys_state()、雙臂實際位姿
  • PC 端腳本連續下目標，跑 10 分鐘無失步
📄 文件：docs/design/wp6-safety-wp7-host.md；測試 test_hostif.c
