認識 STM32 / Cortex-M

🎯 看懂型號命名、選對晶片、知道本專案用哪顆與為什麼。

STM32 命名規則：STM32 F7 46 Z G = 系列 F7（Cortex-M7）· 產品線 46 · 腳位 Z（144-pin）· Flash G（1 MB）。本 repo 名稱是 F426ZG，但實際目標板是 STM32F746ZG（見 CLAUDE.md 說明）：

項目STM32F446ZE（M4 常見入門）STM32F746ZG（本專案）
核心Cortex-M4F @180 MHzCortex-M7 @216 MHz（雙發射 + L1 cache）
記憶體512 KB Flash / 128 KB SRAM1 MB Flash / 320 KB SRAM + TCM
CAN2× bxCAN2× bxCAN（左右臂各一路的關鍵）
FPU單精度單精度（F76x 才有雙精度）
適合一般控制、學習需要算力的控制（14 軸 IK + 軌跡 @500Hz）
為什麼選 F746：雙路獨立 bxCAN（左/右臂各一條匯流排、故障隔離）＋ M7 算力扛得住每 2 ms 一輪的 14 軸運動學。若要走 CAN FD 或 EtherCAT 從站則要換 H7 / 外接，見 docs/design/canopen-vs-ethercat.md。

GPIO · Blink（第一支程式）

🎯 用 HAL 點亮 LED，理解「初始化一次 + 主迴圈」的骨架。
main.c — Nucleo-F746ZG 板載 LED（PB0）每 500ms 閃一次
#include "stm32f7xx_hal.h"

int main(void)
{
    HAL_Init();                        /* SysTick 1ms、NVIC 分組 */
    SystemClock_Config();              /* CubeMX 產生：216 MHz 時脈樹 */

    __HAL_RCC_GPIOB_CLK_ENABLE();      /* GPIO 前一定要先開時脈！ */
    GPIO_InitTypeDef g = {
        .Pin   = GPIO_PIN_0,
        .Mode  = GPIO_MODE_OUTPUT_PP,  /* 推挽輸出 */
        .Pull  = GPIO_NOPULL,
        .Speed = GPIO_SPEED_FREQ_LOW,
    };
    HAL_GPIO_Init(GPIOB, &g);

    while (1) {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
        HAL_Delay(500);                /* 以 SysTick 計時的阻塞延遲 */
    }
}
最常見的坑：忘記 __HAL_RCC_GPIOx_CLK_ENABLE() — 周邊沒開時脈時寫暫存器完全沒反應，也不會報錯。STM32 每個周邊都要先開時脈。

UART printf 除錯

🎯 把 printf 導到序列埠，之後所有除錯都靠它。

Nucleo 板的 ST-Link 內建 Virtual COM Port（F746ZG 上接 USART3 PD8/PD9），把 _write() 轉接到 HAL 即可用 printf：

retarget.c — printf 轉 USART3
#include "stm32f7xx_hal.h"
extern UART_HandleTypeDef huart3;   /* CubeMX 產生，115200-8N1 */

int _write(int fd, char *buf, int len)
{
    (void)fd;
    HAL_UART_Transmit(&huart3, (uint8_t *)buf, (uint16_t)len, 100);
    return len;
}
使用：開機印 banner、週期印狀態
printf("dual-arm fw boot, HAL=%lu\r\n", HAL_GetTickFreq());
printf("[%lu] sys=%s\r\n", HAL_GetTick(), app_sys_state());
常見坑：看到亂碼 → 鮑率沒對上（115200）；printf 沒出來 → 少了 \n 且 newlib 有行緩衝，或 float 格式要在連結器加 -u _printf_float。
💻 對照範例：本 repo 上位機介面 firmware/host/host_if.c 就是用同一條 UART 做文字命令協定（L3 之後會回來看）。

時脈樹 · SysTick · NVIC 中斷

🎯 理解時脈從哪來、1ms 系統節拍怎麼來、中斷優先權怎麼排。
  • 時脈樹：HSE 8MHz → PLL → SYSCLK 216MHz → AHB/APB 分頻。APB1=54MHz 上限，bxCAN 掛在 APB1 — L2 算 CAN 位元時序時就吃這個數字
  • SysTick：Cortex-M 內建 24-bit 計時器，HAL 拿它產生 1ms 節拍（HAL_GetTick()）。本 repo 的安全看門狗就用它記時間戳（app_main.c）
  • NVIC：巢狀向量中斷控制器。搶佔優先權數字越小越優先；控制迴圈 ISR 要排在雜務之上、CAN 收包之下或同級
中斷優先權配置的思路（本專案實際順序）
/* 數字小 = 優先權高
 * prio 1: CAN RX FIFO pending   -- 回授不能丟
 * prio 2: TIM6 500Hz 控制節拍    -- 控制迴圈
 * prio 5: USART3               -- 上位機命令/log
 * SysTick 保持 HAL 預設(最低搶佔之一)，HAL_Delay 才不會卡死 */
HAL_NVIC_SetPriority(CAN1_RX0_IRQn, 1, 0);
HAL_NVIC_SetPriority(TIM6_DAC_IRQn, 2, 0);
HAL_NVIC_SetPriority(USART3_IRQn,   5, 0);
經典死當：在高優先權 ISR 裡呼叫 HAL_Delay() — 它靠 SysTick 中斷遞增 tick，但 SysTick 優先權比你低進不來，永遠等不到 → 卡死。ISR 內只做最短的事。

Timer 週期節拍 · PWM

🎯 做出固定 2ms 的硬體節拍中斷 — 這就是最終專案 500 Hz 控制迴圈的心臟。
tim6_tick.c — TIM6 每 2000µs 進一次中斷（= CONTROL_DT_US）
#include "control_rate.h"   /* CONTROL_DT_US = 2000 (見 firmware/app/) */
TIM_HandleTypeDef htim6;

void tick_timer_init(void)   /* APB1 timer clock = 108 MHz */
{
    __HAL_RCC_TIM6_CLK_ENABLE();
    htim6.Instance = TIM6;
    htim6.Init.Prescaler = 108 - 1;              /* 108MHz/108 = 1 MHz → 1 tick = 1µs */
    htim6.Init.Period    = CONTROL_DT_US - 1;    /* 2000µs = 500 Hz */
    HAL_TIM_Base_Init(&htim6);
    HAL_NVIC_SetPriority(TIM6_DAC_IRQn, 2, 0);
    HAL_NVIC_EnableIRQ(TIM6_DAC_IRQn);
    HAL_TIM_Base_Start_IT(&htim6);
}

void TIM6_DAC_IRQHandler(void) { HAL_TIM_IRQHandler(&htim6); }

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *h)
{
    if (h->Instance == TIM6)
        app_main_tick();     /* 之後整個控制迴圈都掛在這裡(firmware/app/app_main.c) */
}
為什麼用硬體 Timer 而不是 HAL_Delay(2)：控制迴圈要的是「準時」不是「大概」。主迴圈 + delay 會被任何雜務拉長；硬體 timer 中斷的抖動是微秒級。這個差異到專案 B（Linux RT）會再放大成整套 PREEMPT_RT 的理由。
💻 對照範例：firmware/app/control_rate.h（為什麼是 500 Hz 不是 1 kHz — 答案在 L2-11）、firmware/app/app_main.c 的 app_main_tick()。
