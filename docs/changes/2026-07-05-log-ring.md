# log ring（項目 5；WP-H2 計畫的第三個 ring 補齊）

- 日期：2026-07-05
- 分支：`feature/h-sdo-bg-escalation`
- 類型：feat + refactor + test

## 變更摘要

1. **`firmware/engine/eng_log.[ch]`**：RT 域結構化事件日誌——RT 端只寫
   固定紀錄（時戳+等級+代碼+兩參數，無格式化、無 I/O），非 RT 端 pop
   後格式化。SPSC 64 格，滿丟新留舊計 drop（日誌不搶控制預算）。
   事件代碼：SAFE_STOP_ON/OFF、FAULT_EVT（EMCY/CiA402）、OVERRUN_ESC。
2. **寫入點（RT）**：safety agent 的 safe stop 邊緣與故障事件、
   `hn_notify_escalation`（overrun 升級）。**排水口**：pc_master 主執行緒
   格式化到 stderr，結束統計加 `log_drops`。
3. **配套重構**：`sdo_bg.c` 的 EtherCAT step 移到 `bus_ecat.c`
   （新增 `sdo_bg_take_req/respond_ext` 通用鉤子）——sdo_bg 不再連結
   `ec_master`，板端（無 ecat 後端）符號閉合；board Makefile 補
   `engine/spsc_ring.c`、`eng_log.c`、`-Iengine`。

## 動機 / 背景

WP-H2 規劃了 cmd/telemetry/log 三個 ring，前兩個已落地。P6（RT 路徑
零 printf）解掉之後，RT 域的事件（safe stop、EMCY、overrun）需要一條
不破壞即時性的觀測管道——這就是 log ring。

## 影響範圍

- 新增：`engine/eng_log.[ch]`、`tests/test_log.c`
- 修改：`app/app_agents.c`（safety 邊緣/故障記錄）、`engine/harness.c`
  （升級記錄）、`app/app_io_agents.c`（init）、`pc/pc_master_main.c`
  （排水+統計）、`app/sdo_bg.[ch]` + `app/bus_ecat.c`（依賴切割）、
  三個 Makefile
- 控制行為零變化（寫入點都在既有事件邊緣，只添記錄）。

## 驗證方式

`firmware/tests` 4973 檢查 0 失敗；test_log 覆蓋：FIFO 順序、滿→丟新
+drop 計數、欄位/時戳、E2E（cmd ring 下 estop on/off → SAFE_STOP_ON/OFF
各恰一筆——邊緣觸發不重複）。pc_master 建置零警告。
