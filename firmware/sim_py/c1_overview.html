C1 假硬體 — 無馬達驗證 F746 CANopen 主站

STM32F746ZG 主站韌體　×　CANable 2.0 Pro　×　Python CiA402 假從站

slcan · COM111 Mbpspython-can

目這套假硬體的目的

一句話：讓 F746 的 CANopen 主站韌體，在「沒有真實 EYOU PHU 馬達」的情況下，也能被完整開發與驗證。

  • 為什麼需要：真馬達貴、會動有風險、數量少、佈線麻煩；而韌體開發要反覆重啟、反覆測。
  • 驗什麼：主站最關鍵的是 CANopen 交握邏輯（NMT、SDO 讀寫、PDO、CiA402 使能序列、故障處理），這些不需要真實物理馬達就能驗。
  • 怎麼達成：Python 照通信手冊 v1.06 忠實模擬 CiA402 從站，掛在真實 CAN bus 上回應主站，主站「以為」接了真馬達。
  • 好處：安全、可重複、零成本、可注入故障測錯誤處理、可多軸測輪詢。

1硬體接線圖

圖 1・CAN 實體接線
  • 三段連線：F746 PD1/PD0 → 收發器 TTL 側；收發器差動側 CANH/CANL → CANable；CANable → USB(COM11)。
  • 兩顆 120Ω 終端（1 Mbps 對終端敏感，缺一不可）：CANable 板上一顆 + 收發器端一顆。
  • 三方共地：F746、收發器、CANable 的 GND 必須相連。
  • 收發器選 3.3V 版（SN65HVD230），別用 5V 的 TJA1050/MCP2551 直接打進 F746 的 3.3V 腳。

2軟體架構圖

圖 2・軟體分層架構

由上而下即資料流：F746 主站 → CANable → 三層假硬體核心（協定 → 裝置模型 → 物件字典）。右側三個入口工具都掛在協定層上，共用同一份 CiA402Slave + PhuMotor。核心設計是協定與傳輸脫鉤——同一份從站邏輯，離線用斷言測、真機用 python-can 跑、web 用 HTTP 控制。

3分層架構（詳細）

圖 3・4 層 + 入口工具（含 COB-ID / 方法名）

入口三工具都掛在 ① 協定層 上；由上而下呼叫：協定層 handle_frame() → 裝置模型 read_od / write_od / apply_controlword / step → 物件字典。④ 傳輸層 在真機時承載 ① 的收發幀。

4執行期資料流（從站視角）

圖 4・一次 SDO/PDO 交握的收發路徑

主站幀進 handle_frame() 後分兩路：寫路徑（write_od / apply_controlword）與讀路徑（read_od 即時值）→ 匯入 PhuMotor.step(dt) 物理步進 → 產生回應幀（綠色虛線）回傳 F746，完成一次交握。

web 控制台 /cmd 動作

  • mode — 切 8 種運動模式
  • enable / disable — 使能 / 解除
  • quickstop / halt — 急停 / 暫停
  • home — 回零
  • fault / faultreset — 注入 / 清除故障
  • target — 設目標（位置/速度/力矩）
  • trace — 切換 CAN 幀追蹤對象
  • auto — 交還 demo 自驅

8 種運動模式

  • PP(1) 輪廓位置　PV(3) 輪廓速度
  • PT(4) 輪廓力矩　HM(6) 回零
  • CSP(8) 同步位置　CSV(9) 同步速度
  • CST(10) 同步力矩　CSF(13) 同步力控

已驗證：F746 主站開機序列

用 bringup_decode.py 實測抓到的 F746 bring-up（共 22 幀，NMT×3 · READ×10 · WRITE×9）：

NMT   RESET-COMMUNICATION
NMT   PRE-OPERATIONAL
READ  0x1000 Device type        = 0x20192
READ  0x6041 Status word        = 0x40  (switch-on-disabled)
READ  0x26A1 CAN Baudrate       = 1000000 bps
READ  0x26A0 Node-ID            = 1
READ  0x6064 Position Actual    = 0
NMT   START (operational)
WRITE 0x6060 Modes Of Operation = 3   (PV 輪廓速度)
WRITE 0x6083 Profile Accel      = 100000
WRITE 0x6084 Profile Decel      = 100000
WRITE 0x60FF Target Velocity    = 2000
WRITE 0x6040 Control word = 0x06 (shutdown)      -> sw 0x21 ready
WRITE 0x6040 Control word = 0x07 (switch on)     -> sw 0x23 switched-on
WRITE 0x6040 Control word = 0x0F (enable op)     -> sw 0x27 operation-enabled ✔
... 轉 2 秒 ...
WRITE 0x60FF Target Velocity    = 0
WRITE 0x6040 Control word = 0x00 (disable voltage)
韌體 bring-up 邏輯 = 重置通訊 → 讀身分 → 進 operational → 設 PV 模式/目標速度 → 標準三段使能到 0x27 → 轉 2 秒 → 停機。
